# SQL: транзакции и уровни изоляции PostgreSQL

Тема: SQL, transaction, ACID, isolation, Read Committed, Repeatable Read, Serializable, dirty read, lost update, rollback, concurrency. Проверка источника: 2026-10-15.

## Изоляция и наблюдаемость

Транзакция объединяет действия между BEGIN и COMMIT; ROLLBACK отменяет её незавершённые изменения. ACID: atomicity, consistency, isolation, durability. Consistency не означает, что база автоматически знает все бизнес-правила: часть правил выражается ограничениями, часть — логикой приложения.

В PostgreSQL Read Committed — уровень по умолчанию: обычный SELECT видит снимок подтверждённых данных на начало своей команды. Два SELECT в одной транзакции могут увидеть разные подтверждённые изменения другой транзакции. Read Uncommitted в PostgreSQL ведёт себя как Read Committed.

Repeatable Read использует стабильный снимок транзакции и в PostgreSQL исключает phantom reads, но ещё допускает аномалии сериализации. Serializable стремится к результату, эквивалентному последовательному выполнению; возможна ошибка сериализации. Приложение должно уметь безопасно повторять целую транзакцию.

## Учебная конкурентная проверка

В двух отдельных соединениях использовать тестовый счёт `id=42`. В A начать READ COMMITTED, прочитать баланс. В B изменить баланс и подтвердить транзакцию. Повторный SELECT в A увидит подтверждённое изменение. Для Repeatable Read повторить с заново подготовленными данными: второй SELECT в A сохранит прежний снимок. Закончить тестовые транзакции и убрать данные по согласованной процедуре.

## Ошибки и тренировка

`EXPLAIN` показывает план, а `EXPLAIN ANALYZE` действительно выполняет оператор, включая UPDATE, DELETE и INSERT. Результаты измерения не означают, что данные остались прежними. Проверять изменяющие операторы следует в согласованной тестовой среде; транзакция с ROLLBACK может откатить обычные изменения таблиц, но не гарантирует откат внешних эффектов и расхода значений sequence.

Один последовательный тест не воспроизводит гонку. Нужны независимые соединения, управляемые точки синхронизации и проверка итогового инварианта. Проверять также отсутствие частичной записи при ошибке.

Вопрос: «Как проверить последнее место на мероприятие?» Два конкурентных запроса на одно место; ожидается один успех, один корректный отказ, остаток неотрицателен, повтор запроса не создаёт вторую бронь. Конкретный механизм — ограничение, условное UPDATE или блокировка — определяется дизайном.
