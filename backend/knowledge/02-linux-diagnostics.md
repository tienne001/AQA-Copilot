# Linux: командная строка, файлы и диагностика для QA

Тема: Linux, Bash, shell, terminal, logs, логи, pipe, permissions, права, exit code, диагностика. Проверка источников: 2026-10-15.

## Основы shell

Терминал отображает ввод и вывод; shell интерпретирует команды. `pwd` показывает рабочий каталог, `ls -la` — его содержимое, `cd` меняет каталог. Абсолютный путь начинается с `/`, относительный зависит от рабочего каталога. Linux обычно различает регистр имён. Пути с пробелами заключают в кавычки.

Pipe `|` передаёт стандартный вывод первой команды на стандартный ввод второй. `>` перенаправляет stdout с перезаписью, `>>` добавляет в конец, `2>` перенаправляет stderr. Перед записью проверить путь: перенаправление может затереть файл. Права владельца, группы и остальных обозначаются `rwx`; расширять их всем пользователям без причины — плохая диагностика.

## Учебный пример поиска ошибки

В Linux-окружении с существующим файлом `app.log`:

```sh
pwd
ls -l app.log
grep -n 'request_id=qa-42' app.log
tail -n 100 app.log
```

Сначала сопоставить время сбоя и request/correlation ID, затем проследить тот же запрос в зависимостях. Отсутствие совпадений не доказывает отсутствие ошибки: возможно, другой файл, уровень логирования или часовой пояс. Не публиковать токены и персональные данные из логов.

Для systemd-журнала, если сервис называется `my-api.service`:

```sh
journalctl -u my-api.service --since '10 minutes ago' --no-pager
```

Команда зависит от systemd и доступных прав; в контейнере или другом init окружении её может не быть.

## Ошибки и тренировка

Не путать процесс, который существует, с сервисом, готовым отвечать. Проверять наблюдаемый симптом, конфигурацию, логи и конкретный endpoint по очереди. Не начинать с удаления данных или перезагрузки всей машины.

Вопрос: «Permission denied — что проверить?» Путь, владельца, права файла и родительских каталогов, пользователя процесса, mount и контекст доступа. `sudo` меняет полномочия; оно не объясняет причину.
