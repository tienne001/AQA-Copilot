# QA и AQA: стратегия, тест-дизайн и дефекты

Тема: QA, AQA, testing, test design, regression, equivalence partitioning, boundary values, decision table, state transition, severity, priority. Проверка источника: 2026-10-15.

## Что объяснять

Тестирование даёт информацию о качестве и рисках. Успешный набор тестов не доказывает отсутствие дефектов. Статическое тестирование изучает требования, код и другие артефакты без запуска; динамическое проверяет поведение работающей системы. Автоматизация полезна для повторяемых проверок, но требует сопровождения и корректного ожидаемого результата — test oracle.

Уровни тестирования описывают объект: компонент, интеграцию, систему, приёмку. Типы описывают цель: например, функциональную корректность или производительность. Confirmation testing проверяет исправление конкретного дефекта; regression testing ищет побочные последствия изменений. Приоритет проверок определяется риском: вероятностью проблемы и её влиянием.

## Практика тест-дизайна

Учебное требование: принимается целый возраст от 18 до 65 включительно. Классы эквивалентности: меньше 18, допустимый диапазон, больше 65. Для трёхточечного анализа границ взять 17, 18, 19 и 64, 65, 66. Отдельно проверить пропуск, строку и дробь, если интерфейс способен их передать. Эти значения — пример для указанного требования, а не универсальный набор.

Decision table полезна для комбинаций условий: активная подписка и достаточный баланс. State transition testing проверяет состояния и переходы: заказ «создан → оплачен → отправлен», включая запрещённые переходы.

## Дефект и вопросы для тренировки

В отчёте о дефекте нужны окружение, предусловия, минимальные шаги, ожидаемое и фактическое поведение, доказательства. Severity описывает влияние, priority — срочность исправления; шкалы согласуются командой.

Вопрос: что автоматизировать первым? Учебный ответ: частые, стабильные проверки важных рисков с надёжным oracle и управляемыми данными; оценить стоимость поддержки.

Ошибка: считать процент пройденных тестов достаточной оценкой качества без покрытия рисков и анализа пропущенных проверок.
